Sobre este Dicionário

Este Dicionário de Dados foi elaborado como ferramenta pedagógica para a disciplina de Engenharia de Software I, ministrada no Curso Subsequente Noturno do Instituto Federal de Sergipe, Campus Tobias Barreto.

O objetivo é consolidar os principais conceitos, terminologias e definições utilizadas na área de Engenharia de Software, oferecendo aos alunos uma referência rápida e abrangente dos termos estudados ao longo do curso.

Conceitos Fundamentais

Software
Definição: Conjunto de programas + arquivos de configuração + documentação do sistema + documentação do usuário
Sistema de gestão de vendas com documentação e manuais de usuário
Engenharia de Software (ES)
Definição: Disciplina que compreende todos os aspectos da produção de software, desde especificação até manutenção
A ES abrange mais que apenas programação
Sistema
Definição: Conjunto integrado de componentes de software que trabalham juntos para fornecer funcionalidades específicas

Levantamento de Requisitos

Requisitos
Definição: Descrição das necessidades e características que um sistema deve possuir
Requisitos Funcionais
Definição: Descrevem as funcionalidades e comportamentos que o sistema deve executar
O sistema deve permitir que o usuário faça login com email e senha
Requisitos Não-Funcionais
Definição: Restrições sobre serviços ofertados pelo sistema. Definem qualidades gerais do sistema
O sistema deve responder em menos de 2 segundos (Performance)
Requisitos funcionais podem ser sacrificados para atender não-funcionais
Caso de Uso
Definição: Técnica para entender e descrever os requisitos funcionais de um sistema
Caso de Uso: Fazer Login | Ator: Usuário | Ações: Inserir email, senha, clicar login
Casos de uso são textos, não diagramas
Ator
Definição: Entidade externa que interage com o sistema para realizar tarefas
Usuário, Administrador, Sistema de Pagamento
Visão
Definição: Descrição de alto nível dos objetivos e escopo do projeto
Glossário
Definição: Dicionário de termos específicos do domínio do negócio
Termo: Nota Fiscal | Significado: Documento fiscal que registra venda

Análise Orientada a Objetos

Classe
Definição: Descrição abstrata de um conjunto de objetos com características similares
Classe: Produto | Atributos: nome, preço | Operações: calcularDesconto()
Objeto
Definição: Instância de uma classe. Entidade concreta que possui estado e comportamento
Objeto: Notebook Dell Inspiron com preço R$ 2500,00
Atributo
Definição: Propriedade ou característica de uma classe que descreve seu estado
Classe Cliente: CPF, nome, email, telefone
Associação
Definição: Relacionamento entre duas ou mais classes que indica como elas se conectam
Empresa trabalha com Pessoa | Multiplicidade: 1 empresa - * funcionários
Herança
Definição: Mecanismo que permite que uma classe herde atributos e operações de outra classe
Classe Veículo (pai) → Carro, Moto, Caminhão (filhas)
Encapsulamento
Definição: Princípio que oculta os detalhes internos de uma classe, expondo apenas uma interface pública
Modificadores: public, private, protected
Polimorfismo
Definição: Capacidade de um objeto responder a mensagens de diferentes formas
Método calcularArea() em Quadrado, Triângulo, Círculo

Projeto Orientado a Objetos

Operação
Definição: Implementação de uma responsabilidade de uma classe
Operação: calcularDesconto(percentual: float): float
Responsabilidade
Definição: Obrigação de um objeto de fazer algo ou conhecer algo
Classe Pagamento: responsável por fazer o pagamento e conhecer o valor
Princípio de Baixo Acoplamento
Definição: Princípio de design que promove independência entre classes
Benefício: Facilita manutenção, teste e reutilização de código
Princípio de Alta Coesão
Definição: Princípio que promove que elementos de uma classe sejam altamente relacionados
Classe Produto agrupa todos atributos e operações relacionados a produto

UML e Modelagem

UML (Unified Modeling Language)
Definição: Linguagem padronizada para modelagem visual de sistemas orientados a objetos
Objetivo: Comunicação clara entre analistas, designers e desenvolvedores
Diagrama de Casos de Uso
Definição: Diagrama que mostra atores, casos de uso e suas interações com o sistema
Propósito: Visualizar funcionalidades de alto nível do sistema
Diagrama de Classes
Definição: Diagrama que mostra as classes, seus atributos, operações e relacionamentos
Uso: Análise e Projeto orientado a objetos
Diagrama de Sequência
Definição: Diagrama que mostra a ordem temporal das mensagens entre objetos
Propósito: Descrever como um caso de uso é realizado através de interações entre objetos
Multiplicidade
Definição: Notação que indica quantas instâncias de uma classe se relacionam com outra
Empresa 1 ---- * Departamento (Uma empresa tem muitos departamentos)

Padrões de Projeto (Design Patterns)

Padrão de Projeto
Definição: Descrição de um problema e sua solução que pode ser aplicada em muitas situações
Propósito: Facilitar discussão de ideias complexas entre arquitetos e designers
Strategy (Estratégia)
Definição: Padrão comportamental que define uma família de algoritmos intercambiáveis
Diferentes estratégias de cálculo de imposto conforme a região
Singleton
Definição: Padrão criacional que garante que uma classe tenha apenas uma instância
Pool de conexões, Logger, Configurações da aplicação
Factory (Fábrica)
Definição: Padrão criacional que encapsula a criação de objetos
Vantagens: Desacoplamento, flexibilidade na mudança de tipos criados
Observer (Observador)
Definição: Padrão comportamental que define dependência um-para-muitos entre objetos
Quando preço muda, todos os observadores são notificados

Banco de Dados

Banco de Dados
Definição: Coleção organizada de dados relacionados, armazenados e acessíveis de forma persistente
Objetivo: Armazenar, organizar e recuperar dados de forma eficiente
Tabela
Definição: Estrutura de banco de dados composta por linhas (registros) e colunas (campos/atributos)
Tabela Produto: idProduto, nome, preço, estoque
Chave Primária
Definição: Identificador único de cada registro em uma tabela
Características: Não pode ser nula, deve ser única, imutável
Chave Estrangeira
Definição: Campo que referencia a chave primária de outra tabela
idProduto em Pedido referencia idProduto em Produto
SQL (Structured Query Language)
Definição: Linguagem padrão para consulta, inserção, atualização e exclusão de dados
Comandos principais: SELECT, INSERT, UPDATE, DELETE, CREATE, DROP

Persistência

Persistência
Definição: Mecanismo que permite que dados de objetos sejam armazenados permanentemente
Meios: Banco de dados, arquivos, XML, JSON
ORM (Object-Relational Mapping)
Definição: Técnica que mapeia objetos para registros em banco de dados relacional
Exemplos: Hibernate, EclipseLink, SQLAlchemy, Doctrine
DAO (Data Access Object)
Definição: Padrão de design que encapsula acesso aos dados
ProdutoDAO com métodos: salvar(), buscar(), atualizar(), deletar()
Transação
Definição: Sequência de operações executadas atomicamente (tudo ou nada)
Propriedades ACID: Atomicidade, Consistência, Isolamento, Durabilidade
Se algo falhar, toda a transação é revertida
Serialização
Definição: Processo de converter um objeto em formato que pode ser armazenado ou transmitido
Formatos comuns: XML, JSON, Binário
